# Spec：连接模式与出口 IP

> 定稿于 2026-10-06（人在对话里定）。视觉画稿是 claude.ai 上的画布 https://claude.ai/artifact/2mqgJiDPPJTKmQZ7MgrdZL（要用人的 claude.ai 账号登录）。它和 `docs/spec/assets/ui-skins/` 里的 Shoal 画稿是同一套原语；本文只写行为与画稿没画到的部分。

## 0 已定决策

1. **连接模式由设置页的两个开关决定**：「tailnet」「代理」，默认都开，至少要开一个（只剩一个开着时，它的开关变淡、点了不生效）。三种组合分别是：tailnet + 代理（默认）、仅 tailnet、仅代理。VPN 开着时拨动开关，服务会重启一次（`RESTART`）。状态栏快捷开关和「始终开启的 VPN」都按设置里的模式启动。
   - 例外：没有配置时拨开「代理」，只保存偏好并提示先导入配置，不重启。这时重启会因为没有配置而启动失败，把正在用的仅 tailnet 连接一起断掉；之后导入配置触发的重启再切到新模式。提示放在设置页「连接」浮岛下的那行说明里：开着代理而没有配置时多一句「还没有配置：先导入一份配置，代理才会启用。」，一直显示到导入为止。这时把代理拨回去，内核本来就在跑仅 tailnet，同样不重启。
2. **仅 tailnet** 和官方 App 一样，VpnService 只路由 tailnet 地址：`100.64.0.0/10` 和 `fd7a:115c:a1e0::/48`。其它流量和 DNS 都不进 VPN。这个模式不读配置（没有配置也能连）。IPv6 地址照样要加，否则 VpnService 会把整个 IPv6 拦下。
   - 内核不劫持 53 端口：发往 tailnet 上 DNS 服务器（`100.x.y.z:53`）的查询同其它流量一样交给 `ts`。注入时要显式写空的 `dns-hijack`：mihomo 的 tun 缺省就劫持全部 53 端口，省略等于照旧劫持。
   - 导入配置、替换 GeoIP 库时，内核和设置里的模式都是仅 tailnet 就不重启：这个模式两样都不读，重启只会让 tailnet 断几秒。设置里已经拨开了「代理」（上一条的例外）时，导入配置照常重启，靠它切到新模式；只换了 GeoIP 库、还是没有配置时仍不重启。
   - 已知限制：接管的是整个 `100.64.0.0/10`，不是 tailnet 里实际有的那几个地址。底层网络自己用这个段的地址时（运营商 CGNAT 的网关、同一网段里的设备），那些地址会不通。按节点逐条下发路由要随节点增减重建 VPN 接口，没有这样做。
3. **仅代理** 不起 tsnet。`ts` 换成连不上的占位节点（`127.0.0.1:1`），经过它的节点会立即失败，配置照样解析得过。用不了的节点在节点页变淡、不能选，延迟显示「不可用」；如果当前出口要经过 `ts`，连接页显示「出口不可用」，并给一个「换一个出口」按钮。节点的前置（`dialer-proxy`）指向代理组时，按组当前选中的成员算：选中的是 `ts`、或选中的节点自己要经过 `ts`，这个节点同样用不了；链路里组保留，它的前面多一跳，就是组里选中的那个成员（`ts → 组 → 节点`）。组成员自己是组时不往里展开。
4. **皮肤只留 Shoal**：夜航、Tonal 已删（代码、字体、图标、画稿副本都删了），设置页没有「皮肤」行。
5. **连接页显示出口 IP 和归属地**，有三种摆法，在设置「外观 → 连接页的出口 IP」里切换：
   - 状态卡里一行；
   - 独立卡片（默认）；
   - 链路的出口那一跳下面。仅 tailnet 时没有链路卡，这种摆法退回成独立卡片。
6. **节点页每个节点都显示记下的出口 IP**，写法同摆法 C，后面跟一个「机房 / 住宅 / 移动网络」小标签。

## 1 出口 IP

- **数据源**：`http://ip-api.com/json/?lang=zh-CN&fields=…`（免费，只有 http，限 45 次/分钟）。hosting 为真时显示「机房」，mobile 为真时显示「移动网络」，其余显示「住宅」。地名是中文。
- **怎么查**：
  - 经节点查：Go 侧的 `ExitIP(node)` 直接用 `proxydialer` 经该节点拨号，不切换当前选中的节点，域名交给节点的远端解析。
  - 仅 tailnet：本 App 进程被排除在 VPN 之外，直接查到的就是手机自己网络的出口。Kotlin 用 `HttpURLConnection` 发请求，`network_security_config` 只对 ip-api.com 放行明文。明文应答可能被劫持，所以最多读 4 KiB、整次请求限 8 秒（同 Go 侧经节点查的上限）。
- **什么时候查**：
  - 当前出口在以下时机重查：连上、切换节点、首页刷新；仅 tailnet 模式下切网后也重查（去抖 3 秒）。主组选中的是子组时，「当前出口」是沿各组的选中项一路找到的那个节点：在子组里换节点同样重查，查到的 IP 记在那个节点名下；仅代理模式下判断「出口不可用」看的也是它。
  - 首次查询失败时，按 3 秒、5 秒、8 秒的间隔重试，都失败才显示「查不到」。原因是 VPN 刚起来时，经 `ts` 的通路还是冷的。
  - 测延迟测完之后，给还没记下 IP 的节点补查，同时最多查 3 个。已经记下的节点不重查。
- **记录**：按「节点名|服务器地址」记在 `files/exitip.json`。组、DIRECT 这类没有地址的成员不记。重新导入配置后，名字或地址变了的那条记录随之删掉。
- **隐私**：IP 和查询结果都不写进日志，失败时只记异常类名。

## 2 各模式下的界面（画稿第二、三行）

| | tailnet + 代理 | 仅 tailnet | 仅代理 |
|---|---|---|---|
| 状态副文字 | 代理与 tailnet 都已就绪 | 仅 tailnet · 其它流量直接走手机网络 | 仅代理 · tailnet 未启用 |
| 统计格 | 出口延迟 / tailnet 在线 / 可选出口 | tailnet 在线 / 直连 / 中继 | 出口延迟 / 可选出口；有经 `ts` 的节点时第二格写「可用出口 a/b」 |
| 链路卡 | 有 | 无 | 有；`ts` 那一跳粉底，写「仅代理模式下未启用」 |
| 列表 | tailnet、配置、连接模式 | 多一行「代理 · 未启用」 | tailnet 行变淡，写「未启用」 |
| tailnet 标签 | 照旧 | 照旧 | 「tailnet 未启用」 |

- 「连接模式」这一行三种模式下都有，点了进设置页。
- 通知正文：仅代理写「仅代理 · 出口 X」，仅 tailnet 写「仅 tailnet <IP>」。磁贴的「待登录」只在开了 tailnet 时出现。

## 3 画稿与实现的差异（已接受）

- 底栏里未启用的那一项，画稿画成了变淡，实现没有做：点进去看到的是「tailnet 未启用」或节点页里变淡的节点。
- 节点页的 IP 行横跨整行宽度，排在延迟徽章下面：画稿里它挤在名字那一列，真机上 IP 会被截断。
